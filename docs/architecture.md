# Architecture map

> Generated by `python tools/generate_architecture.py`. Do not edit this file manually.

This map covers the active Python package in `src/`.
`src/nodes/` contains the ComfyUI nodes and their exports; `src/core/` contains shared logic and bundled JSON schemas. `src/__init__.py` registers the plugin and local HTTP routes.

## Pipeline flow

```mermaid
flowchart TD
    selector["Select Chapters"] --> adapter["Cinematic Chapter Adapter"]
    config --> adapter
    selector --> evidence["Character Evidence Extractor"]
    config --> evidence
    evidence --> evidence_json["Independent chapter evidence and verbatim source JSON"]
    evidence_json --> evidence_loader["Load Character Evidence"]
    evidence --> profiles["Consolidate Character Profiles"]
    evidence_loader --> profiles
    config --> profiles
    profiles --> visual_profiles["Character Visual Profile Generator"]
    config --> visual_profiles
    visual_profiles --> visual_json["Editable English character visual profiles JSON"]
    profiles --> profiles_json["Source-grounded editable character profiles JSON"]
    adapter --> adapted["Per-chapter sequence/source/adaptation JSON"]
    adapted --> extract
    adapted --> loader["Load Cinematic Chapters"]
    loader --> extract
    config["LM Studio Configuration"] --> extract["Extract Chapter References"]
    extract --> consolidate["Consolidate References"]
    consolidate --> timeline["Canonical entity timelines: chapter / sequence / phase"]
    extract --> local["Editable local identity links in chapter catalogs"]
    local --> consolidate
    consolidate --> designs["Prepare stable visual designs"]
    designs --> generate["Generate H3 Prompts"]
    consolidate --> generate
    selector --> generate
    config --> generate
    generate --> review["H3 validation, camera processing, temporal review/repair"]
```

The node wrappers coordinate filesystem access, configuration snapshots and run outputs. The three `pipeline_step*` modules contain the LLM-facing stage implementations.
The standalone cinematic adapter uses `cinematic_adaptation` and the shared LM Studio JSON transport. Its ordered phases feed extraction; catalogs and registries retain temporal observations.
`narrative_validation` reviews adaptation source fidelity and transitions before targeted sequence repairs, and reviews extracted phases using only earlier identity context. Rejected phase results are not cached; persistent semantic defects stop the stage.
Adaptation repairs use the full passage source and neighboring sequences as context. When enabled targeted corrections are exhausted, one final source-bound reconstruction of the passage is reviewed before acceptance.

`reference_timeline` validates cinematic catalogs, merges observations without rewriting them, computes first occurrences and provides exact-address state lookup. Identity reconciliation and duplicate audits exclude temporal state; base image briefs use stable identity only.
Local `link_to_local_id` decisions are validated before model work and grouped before reconciliation. Every source ID maps to the unified entity, retaining all phase observations and unchanged chapter sequences. Image briefs cover all consolidated entities. `editable_schemas` validates and exports the visual design schema; extraction exports the chapter catalog schema.
